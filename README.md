# 茶叶拼配审评台

审评员对一个拼配批次打香气、滋味、汤色，并声明季节。服务端按 0.3 / 0.5 / 0.2 加权，分数达到该批次声明季节的放行线才通过。四季各存一条放行线（默认 7），审评员可在「季节档」专页调线；每次改线追加一条履历（季节、旧线、新线、改线人、时刻），履历与已落库结论永不被后续改线改写。提交后只替换表格里新的一行，不整页跳转。

这是制茶审评，不是菜谱，也不是饮食记录。

```bash
cd projects/13-tea-blend-cupping
docker compose up --build
```

## 验收

1. taster 登录后看到春茶-A 通过、夏茶-C 不通过（行内带季节）。
2. 不声明季节直接提交，服务端拒交（400）。
3. 季节档页把夏档从 7 改成 8.5：履历出现「夏 7→8.5 taster 时刻」一行；再改其它值，旧履历行仍保留。
4. 声明夏季递交香气 9 / 滋味 8 / 汤色 6（加权 7.9）判不通过；声明春季且春档仍为 7，同样三项判通过。
5. 改线只影响该季新交评，其它季节与此前已落库的结论不变。
6. observer 登录后没有提交表单，季节档页只能看线表与履历，改线与交评均被拒绝（403）。
